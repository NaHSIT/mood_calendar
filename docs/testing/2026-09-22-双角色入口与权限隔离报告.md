# 双角色入口与权限隔离报告

## 结论

应用已调整为一个系统、两个独立入口、两套界面。学生演示身份进入个人情绪管理空间，教师演示身份直接进入脱敏预警工作台。学生页面不再提供教师入口，退出当前演示身份后才能返回独立入口重新选择角色。

当前实现仍是本地原型，没有接入学校统一身份认证。正式部署时应把独立演示入口替换为 IdentityAuthenticator，并根据服务端验证后的 ActorRole 执行相同的角色落地逻辑；客户端传入的角色字符串不能作为授权依据。

## 问题比对与处理

| 编号 | 原问题 | 处理结果 |
|---|---|---|
| R01 | 应用启动后没有角色分流 | 启动页增加学生和教师两个独立演示入口，角色通过统一落地映射进入不同应用外壳 |
| R02 | 学生导航混入教师工作台 | 学生端删除照护聚合页和教师入口，改为情绪日历、数据洞察、随访任务、我的 |
| R03 | 学生首页职责不清 | 首页按记录心情、本月情绪日历、状态评估、条件式随访提示排列 |
| R04 | 教师端不是独立首页 | 教师登录后直接进入预警工作台，仅保留预警工作台和账号设置 |
| R05 | 教师详情信息层级混乱 | 固定为预警基本信息、工作摘要、当前处理操作、状态与处理历史四段 |
| R06 | 风险原因只靠统一颜色表达 | 将量表缺失或过期归为评估提醒，将安全阈值归为安全预警，生理信号归为辅助标签 |
| R07 | 工单状态与学生任务状态混淆 | 教师工单沿用待确认、处理中、已结束；学生端使用待完成任务和关怀状态文案 |
| R08 | 量表提交使用固定学生字符串 | 提交时从受信 SessionProvider 读取当前学生标识，仓库继续校验本人归属 |

## 学生端

学生端四个主导航分别承担以下职责：

- 情绪日历：记录今日心情、本月日期概览、量表入口和本人记录。
- 数据洞察：深度洞察、周月趋势、情绪频次和本人量表历史。
- 随访任务：打卡、量表复测、关怀联系状态和退出申请；未进入随访时显示空状态。
- 我的：健康数据授权、本人原始数据入口、删除操作、隐私说明和账号设置。

学生端不包含预警队列、工单状态、确认预警、启动干预、结束工单或退出审核按钮。

## 教师端

教师工作台默认显示待确认队列，并可切换处理中和已结束。列表只展示脱敏代号、关注等级、触发原因和更新时间。详情页根据工单状态只显示当前允许的操作：待确认时确认预警，确认后启动干预，处理中填写联系及处理记录，已结束时只读查看结果。

教师账号页明确说明访问范围。教师端模型只使用 TeacherAlertSummary、InterventionCase 和必要随访审核信息，不包含 MoodRecord、量表逐题答案或 RawHealthSample。

## 接口权限核对

- 学生量表、授权和原始健康数据仓库要求 ActorRole.STUDENT，并校验 actorId 与 ownerId 一致。
- 教师预警和工单仓库要求 ActorRole.TEACHER，并通过教师学生分配关系校验访问范围。
- 内部风险计算和管理写入要求 ActorRole.SYSTEM，学生或教师会话不能直接调用。
- DEMO 与 REAL 数据域隔离，跨域访问返回 Forbidden。
- 页面隐藏仅用于减少混乱，真正的权限拒绝仍在仓库和访问策略层执行。

## 验证范围

本轮执行 Kotlin 编译、66 项 JVM 单元测试、Debug APK 构建、Lint 和 Git 差异检查，全部通过；新增学生、教师和内部系统身份的落地页映射测试。根据要求没有进行真机测试，因此具体设备上的四导航宽度、大字体、横屏和系统返回行为不属于本轮验证结论。
