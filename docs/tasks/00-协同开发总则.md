# 心情日历：多窗口开发任务书

本批任务仅实现本地原型：量表 → 辅助生理信号 → 分级预警 → 教师干预 → AA 随访。健康硬件、学校平台、真实推送不接入。不得把模拟投递称为真实发送成功。

## 已核实的起点

- Android 单 app 工程，Kotlin / Compose / Room，包名 `com.example.mdd_calender`。
- 现有数据库版本为 3，包含心情和纪念日；已有数据必须保留。
- 尚无量表、用户权限、教师工作台和 AA 模块。
- 初次检查时没有 Git 仓库；现已安排 Git 初始化与独立 worktree 协作，具体分支、目录和同步步骤见 `09-Git分支与窗口启动.md`。不要在同一工作目录开多个开发窗口。

## 任务划分及顺序

| 窗口 | 任务书 | 依赖 |
|---|---|---|
| A | 01-公共契约与隐私存储 | 首先完成接口、空实现和可用的本地身份上下文，发布契约冻结通知 |
| B | 02-学生量表与测评中心 | A 契约冻结后开发，可与 C/D/E/F 并行 |
| C | 03-健康授权与接入框架 | 同上 |
| D | 04-评估规则与预警事件 | 同上；使用合成输入，不必等待 B/C 页面 |
| E | 05-教师工作台与平台接口 | 同上；使用合成预警，不必等待 D |
| F | 06-AA随访与学生任务 | 同上；使用合成干预事件，不必等待 E |
| G | 07-应用集成与闭环验收 | 前期检查构建环境；各模块交付后负责接线与总体验收 |

A 可在冻结接口后继续完善存储；其他窗口通过接口及各自测试替身开发。各窗口使用独立 worktree 和构建目录；G 在 develop 的约定集成检查点执行全量验证。公共接口经合并进入 develop 后，各功能分支才能同步使用；其他 worktree 的未提交文件不会自动出现。

## 所有窗口必须遵守

1. 先读本文件、自己的任务书和 `08-公共接口与业务约定.md`，再查看项目中的实际约束。
2. 只修改任务书分配的目录；不要整理、回退或格式化其他窗口代码。目录以任务书为准，未分配的新公共文件交 A/G 协调。
3. A 独占公共领域契约、存储、会话权限及数据库迁移；G 独占现有导航、入口、Gradle 和旧分析页。其他窗口不得自行添加依赖或修改数据库注册。
4. 新页面接收专属 ViewModel / 接口及导航回调，不继续扩张旧 `MoodViewModel`。
5. 跨模块调用只依赖 A 冻结的接口；不得直接依赖其他功能模块的 DAO、内部 UI 或实现类。
6. 需要变更公共接口时，在自己的交付文件记录提案、原因和受影响方，由 A 统一修改并通知。禁止各窗口分别定义同名公共类型。
7. 使用虚构学生和模拟健康数据。日志、通知预览、演示截图不得包含真实敏感信息。
8. 量表是筛查依据，不输出疾病确诊。未知、未授权、缺失数据不等于正常。健康数据不能降低量表触发的关注等级。
9. 本地角色切换只供独立演示数据集使用，不得借切换角色查看真实学生库。正式身份鉴别与服务端授权明确标注为后续能力。
10. 不联网上报、不发送真实教师消息、不部署平台。本次仅预留适配接口。

## 交付格式

每个窗口创建 `docs/tasks/handoffs/<窗口字母>.md`，内容包含：完成项、修改文件、公开接口/页面签名、验证命令和结果、未完成项、集成步骤、依赖请求。不得把未运行的测试写成通过。

任务完成后只声明本模块可集成；全项目完成由 G 根据闭环验收确认。新增依赖须写清用途和版本，由 G 统一落地。

## 统一完成标准

- 保留原有心情记录、照片入口、日历和纪念日流程。
- 学生可完成量表、管理健康授权、查看个人测评及随访任务。
- 教师只能访问责任范围内的预警摘要及干预随访工作信息，看不到原始健康数据、日记或逐题答案。
- 未授权健康数据仍能产生量表预警；模拟投递有回执、重试和明确演示标识。
- 干预启动自动进入 AA，任务可完成、逾期可提示，退出必须有人工审核记录。
- 每次评估、预警、干预、AA 状态迁移均能追溯事件及规则版本。

## 信息边界

学生年龄段、监护人授权要求、学校响应时限、量表中文适用版本及专业审核策略待学校确认，不阻塞虚构数据原型。不声称本原型已满足正式校园部署或临床使用条件。AA 是业务跟踪层级，不是诊断。
