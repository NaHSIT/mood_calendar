# 窗口 E：教师工作台、消息投递与学校平台接口

## 目标及边界

实现教师接收预警、确认和启动分级干预的本地演示。先读 00/08；独占 `feature/teacher/`、`integration/school/` 及对应测试。不接真实学校平台、不发送真实通知、不修改 AA 实现。

## 工作清单

1. 教师消息箱提供待确认、处理中、已结束筛选；详情仅显示白名单摘要及最少必要干预工作信息。
2. 责任范围校验使用 A 仓储，不能只在列表隐藏其他学生。按事件 ID 访问详情也必须鉴权。通知预览不显示学生姓名和敏感标签。
3. 实现未接入/模拟 `SchoolPlatformGateway`；形成接口说明，包含协议版本、幂等键、超时、错误、回执及未来认证扩展。平台 endpoint 和密钥不硬编码。
4. 提供持久投递队列：模拟送达、失败重试、永久失败、教师确认分开；重启可恢复，重试不重复创建教师事件。
5. 发送前校验当前摘要和授权修订，避免撤回后的辅助内容继续发送。对量表独立预警继续投递。
6. 教师可确认、记录联系、开始干预、制定/查看任务、申请结案；中度和高度提供不同的可配置处置步骤，高度优先转交专业人员入口仅演示。
7. 正式开始干预时调用公共事务服务或可靠事件，由 A/F 保证 AA 入库。失败时不能显示闭环完成；不要另建 AA 表。
8. 对未确认预警按可配置时限产生升级待办；演示用虚拟时钟，不假设学校已有全天候接警人员。

## 验收

- 越权学生代号/事件 ID 被拒绝；序列化负载完全不含原始健康数据和量表答案。
- 覆盖重复投递、失败重试、重启恢复、迟到回执、撤权竞态、无人确认、事件升级。
- 界面清楚区分模拟送达和教师确认；未接入不能显示真实推送成功。
- 交付教师页面、适配契约示例、脱敏 payload 样例、测试及 `handoffs/E.md`。
