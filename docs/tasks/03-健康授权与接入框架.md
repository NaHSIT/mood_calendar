# 窗口 C：健康授权与设备接入框架

## 目标及边界

只实现可替换适配器、授权管理和虚构数据演示，不读取真实硬件或手机健康数据。先读 00 和 08；独占 `feature/health/` 及对应测试，依赖 A 的授权及健康仓储。

## 工作清单

1. 实现 `HealthDataProvider` 的未接入版本、演示版本；定义后续手机健康平台/手环适配器的能力边界，不增加真实 SDK、系统权限或后台采集。
2. 新建健康管理页：心率、睡眠分别授权，默认关闭；展示用途、可见范围、数据状态、授权撤回及删除原始数据入口。
3. 为学生本人提供原始数据页面，仅演示身份下显示明确标注的模拟曲线/列表；未接入显示真实空状态，不能伪造实时监测。
4. 实现粗粒度 `PhysiologySignalExtractor`。使用明确模拟场景或可配置规则，不宣称心率/睡眠阈值具有临床有效性。输出质量、时效、模拟标记和授权版本，不输出原始序列给教师。
5. 撤回时取消任务，在途回调再次核对授权版本；撤回后到达的结果不得保存或触发辅助评估。重新授权不能复活已取消的旧任务。
6. 向 G/D 提供授权变更事件，用于清除待发健康内容与重新计算摘要；量表预警不随健康授权关闭。
7. 删除原始数据与关闭同步区分，明确已送达摘要无法从教师记忆中收回；原始数据不得进入日志。

## 验收

- 未授权时不调用 provider 拉取；部分授权只处理允许类型；模拟与真实数据域完全分开。
- 测试撤回与同步同时发生、迟到回调、重启后仍关闭、数据过期/低质量、无数据、重复授权。
- 教师接口不能返回原始数据；查看页无访问权限时显示拒绝，而非伪装空数据。
- 交付页面/适配签名、模拟场景表及 `handoffs/C.md`。
