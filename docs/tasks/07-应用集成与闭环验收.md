# 窗口 G：应用集成、旧功能兼容与闭环验收

## 目标及文件归属

先读 00/08；负责整体可运行和各模块连接。独占 `integration/app/`、现有 MainActivity、AppNavigation、MainScreen、HomeScreen、AnalysisScreen、SettingsScreen、MoodViewModel、Gradle 配置、AndroidManifest、备份规则及集成测试。不修改 A–F 独占实现；缺陷反馈相应窗口。

## 工作清单

1. 前期核实构建环境及现有构建状态，记录基线。检查 minSdk 24 与现有 java.time 使用的兼容性，按实际依赖与工具链处理；不得凭旧产物宣称源码构建通过。
2. 统一处理各窗口提出的新依赖和 manifest/备份需求。备份不得导出未加密健康/量表数据；评估密钥不可随备份恢复时的行为。
3. 装配专属服务/ViewModel，接入测评中心、健康授权、学生随访和独立教师演示工作台。角色演示数据集隔离，真实数据不能通过角色切换展示。
4. 测评提交 → D 评估 → 预警持久化 → E 模拟投递 → 教师启动干预 → F/A 原子入库 → 生成任务 → 复测关联 → 退出审核，逐段接通且支持重启恢复。
5. 授权撤回接通 C、D、E，处理在途回调和待发摘要。真实平台未接入时界面如实显示。
6. 将旧 AnalysisScreen 中关键词疾病推断替换为量表结果和待评估状态；保留普通心情分布/记录浏览。未填写量表不得由旧分析器补造诊断。
7. 保留原日历、记录编辑、图片、纪念日和个性化功能。修改范围内修复编辑覆盖 createdAt 的问题；图片持久访问问题如需变更明确记录，不混入其他窗口提交。
8. 统一导航返回、加载/空/错误状态、无障碍描述和隐私文案；不得仅因存在页面就宣称功能完成。

## 必须演示的端到端场景

1. 无手环、无健康授权：完成中度量表 → 模拟教师预警 → 确认并开始干预 → 自动 AA 入库 → 完成随访测评 → 人工退出。
2. 已授权模拟生理异常：同样量表基础等级不变，摘要出现辅助标签；教师始终看不到详细数据。
3. 同步中撤权：迟到数据丢弃，待发摘要去除生理标签，量表预警保留。
4. 无量表/过期量表：显示待评估，不能显示正常；历史预警仍可处置。
5. 安全关注、重复提交、模拟投递失败及重启：不漏事件、不重复干预/入库，不假报消息已确认。
6. 其他学生/非责任教师尝试列表、详情和写入：拒绝访问。
7. 原 v3 数据库迁移后，既有日记及纪念日仍在。

## 验收交付

- 在约定的稳定集成检查点运行 `gradlew.bat :app:testDebugUnitTest :app:assembleDebug`，并按环境执行 `:app:lintDebug`；仪器/迁移测试需设备时说明具体环境与结果。
- 有设备时验证实际 UI 导航、权限隔离、旋转/重启、离线流程；无设备时明确未验证，不以单元测试替代真机结论。
- 交付 `handoffs/G.md`：构建结果、APK 路径（仅构建成功后）、演示步骤、遗留问题、生产接入边界。
- 汇总用户年龄适配、中文量表审核、学校策略、真实认证/推送等外部依赖。不得为通过演示移除隐私检查、清空旧库或吞掉失败。
