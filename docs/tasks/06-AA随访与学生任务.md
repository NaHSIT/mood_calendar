# 窗口 F：AA 长效跟踪与学生随访任务

## 目标及边界

实现干预后的持续随访及人工退出。先读 00/08；独占 `feature/followup/` 及对应测试。AA 仅为业务跟踪层级；不得从量表分数直接自动入库，也不改教师消息模块。

## 工作清单

1. 消费“干预正式启动”事件，调用 A 的事务能力创建/复用 AA 档案；重复事件和应用重启不重复入库，新增预警关联到当前档案。
2. 定义可配置随访策略：简短心情打卡、完整量表复测、教师联系。增加频次不改变 PHQ-9/GAD-7 的两周回顾窗口。
3. 实现学生任务列表、到期提醒、完成记录与个人随访状态；接入 B 的测评回调，只有成功保存的对应测评才能完成复测任务。
4. 实现教师随访列表/详情组件，展示责任范围内任务完成度、待联系及 AA 状态，不显示原始数据或逐题答案。
5. 到期、逾期、暂停、完成、取消明确区分；未打卡产生待联系，不直接升为心理高风险。
6. 退出需满足可配置稳定观察条件、没有未处理安全关注，并由责任人审核。记录依据及审核时间，单次低分不能自动退出。
7. 退出后取消未来未执行任务，保留历史；再次干预可重新入库。转交责任人时明确归属更新，避免两位教师同时越权处理。
8. 提供可恢复的任务生成逻辑与可注入时钟，重启不重建重复任务。提醒调度交 G 接 Android 能力，本窗口不擅自增加平台依赖。

## 验收

- 覆盖重复启动干预、事务失败恢复、不同预警同一学生、逾期、重复完成、退出拒绝/批准、再次入库。
- 学生只能看到自己的任务，教师只能操作职责范围；手动伪造 assessmentId 不能完成任务。
- 明确标注演示随访周期，不宣称频次已获专业审核。
- 交付业务服务、学生/教师组件签名、状态机测试及 `handoffs/F.md`。
