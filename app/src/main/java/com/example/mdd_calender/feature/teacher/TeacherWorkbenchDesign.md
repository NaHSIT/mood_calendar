# 教师工作台实现设计

本文件是窗口 E 在公共契约冻结前的模块内设计，不定义公共领域模型，也不代表功能已经实现。

## 页面边界

工作台仅消费 A 提供的教师白名单摘要和最少必要工作信息。页面不得接收或缓存量表逐题答案、详细分数、日记、原始心率、原始睡眠数据或学生真实姓名。

建议由 G 通过以下页面入口接线，具体 Kotlin 类型以 A 冻结签名为准：

- `TeacherInboxRoute(onOpenAlert, onBack)`：展示待确认、处理中、已结束三个筛选；加载、拒绝访问、暂时失败和真实空列表必须区分。
- `TeacherAlertDetailRoute(alertId, onBack, onOpenIntervention)`：再次按 `alertId` 向仓储鉴权，不能信任列表页已过滤。
- `TeacherInterventionRoute(alertId, onBack, onStarted)`：确认、联系记录、启动干预、任务计划和申请结案；启动失败时保留原状态并给出可重试错误。

页面只传稳定 ID 和导航回调，不把完整实体放进导航参数。

## 权限与最小披露

每个读取和写入用例都从 `SessionProvider` 获取可信身份，并由 A 的仓储执行责任范围校验：

| 操作 | 责任教师 | 非责任教师/学生身份 | 返回内容 |
|---|---|---|---|
| 告警列表 | 允许 | 显式拒绝 | 白名单摘要 |
| 告警详情 | 允许且按 ID 复核 | 显式拒绝 | 摘要及处置状态 |
| 确认/联系/启动干预 | 允许且写入前复核 | 显式拒绝 | 最少必要结果和审计引用 |
| 通知预览 | 允许 | 显式拒绝 | 事件代号、优先级、时间，不含姓名和敏感标签 |

越权不能伪装成空数据或“记录不存在”。UI 可使用统一的无权限文案，但日志不得写入敏感请求正文。

## 状态与命令

教师确认和平台投递是两个独立维度。建议 ViewModel 暴露不可变页面状态，并让命令带客户端操作 ID 以防重复点击：

- 告警处置：`PENDING_ACK -> ACKNOWLEDGED -> INTERVENING -> PENDING_CLOSE -> CLOSED`。
- 投递：`PENDING -> SIMULATED_DELIVERED | RETRY_SCHEDULED | PERMANENT_FAILURE`。
- “模拟送达”只能说明演示网关已返回回执，绝不能显示为“教师已确认”。
- 同一命令重复提交必须返回原结果；进程重启后仍由持久记录判定幂等。
- 启动干预只有在 A 的事务服务确认干预与 AA 事件可靠落地后才进入成功状态。

## 处置步骤

处置步骤通过策略配置注入，不在 UI 中写死学校时限或临床结论：

- 中度：确认摘要、记录联系、安排后续任务、必要时转介。
- 高度：优先人工安全评估、联系校内专业人员、记录处置；不能仅凭量表或辅助信号声称紧急危险。
- 未确认升级：使用可注入时钟形成“升级待办”，不自动向真实人员发送通知。

## 授权撤回竞态

投递前必须重新读取当前告警摘要和授权修订：

1. 队列只保存 `alertId`、目标代号、幂等键和计划时间，不长期保存完整 payload。
2. 每次尝试前由仓储生成当前白名单摘要。
3. 若授权修订过期，取消本次尝试并重新生成不含失效生理标签的 payload。
4. 量表独立触发的告警继续投递；已送达历史仅保留最小审计，不宣称可以撤回教师已看到的信息。

## 必测场景

- 责任教师列表和按 ID 详情均成功；非责任教师对两者均收到显式拒绝。
- 重复确认、重复启动干预、快速连点不会创建重复处置或 AA 入库事件。
- 模拟送达、教师确认、失败重试和永久失败分别展示。
- 进程重启恢复待发/待重试记录，迟到回执不能覆盖更晚状态。
- 发送前发生健康授权撤回时，payload 移除相关辅助标签但保留量表告警。
- 超过配置时限生成一次升级待办；虚拟时钟重复推进不重复创建。
- 序列化结果通过字段白名单和禁止词测试，确保不含逐题答案、详细分数、日记、原始健康数据及真实姓名。
